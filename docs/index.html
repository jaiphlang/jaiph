Your first sample

script run_tests = 'npm test'

export def main() {
  # When the tests fail, an agent fixes the code
  # and the tests run again.
  run_tests() recover (failure) {
    prompt "The tests failed. Fix the code. ${failure}"
  }

  return "tests pass"
}

This program runs a project's tests. When the tests fail, it sends the failure to an agent, and then it runs the tests again. The Graph tab shows the steps as a chart, and the Terminal Output tab shows one run.

What Jaiph changes

An agent on its own

  • You describe a job with several steps, and the agent decides the steps again on every run.
  • You can't review the steps before the run, and you can't test them.
  • When a run goes wrong, you read a long transcript to find out where.

The same job in Jaiph

  • The steps are in one small file that you review like any other code.
  • Scripts do the exact work, and the agent is called only where a step needs judgment.
  • Jaiph saves the output of every step, so you can see which step failed and why.

What is Jaiph?

Jaiph is a small language and a runtime for jobs that mix AI agents with ordinary scripts in Bash, Python, Node, or another language. You write the steps in a .jh file. Jaiph runs the steps in order, saves what each step printed, and stops with a clear error when a step fails.

One file, three ways to run

The same file runs from the command line with jaiph run, as tools for Claude Code or Cursor with jaiph mcp, and as an HTTP API with jaiph serve.

Tests that don't call an agent

A test file replaces each agent reply with fixed text, so a test gives the same result on every run and can run in CI.

A record of every run

Jaiph saves the output of every step and every agent reply under .jaiph/runs/, and it can export traces to your monitoring tools.

Secrets are granted by name

A script gets a secret from your shell only when the file asks for that secret and you grant it when you start the run.

Isolation is your choice

Jaiph runs on the machine where you start it, and it is not a sandbox. To isolate a run, start it in a container. Each release publishes a runner image.

Any agent, open source

Cursor, Claude, and Codex work today, and one config line switches between them. The source is under the Apache 2.0 license, and Jaiph has no tracking.

Samples

#!/usr/bin/env jaiph

# check the name before calling the agent
def valid_name(name_arg) {
  return match name_arg {
    /[A-Z][a-z]+/ => name_arg
    _ => fail "You provided an invalid name :("
  }
}

# jaiph run starts at export def main
export def main(name_arg) {
  const name = valid_name(name_arg)

  # a prompt calls an agent (Cursor by default)
  const response = prompt """
    Say hello to ${name} and provide a fun fact
    about a person with the same name.
    Respond with a single line.
    Do not inspect files or run tools.
  """

  return response
}

A .jh file is a program. A def is a procedure, a prompt step calls an agent, and a script runs code. jaiph run starts at export def main.

To get structured data from a prompt, add returns "{ hello: string, fact: string }" to the prompt and read ${response.hello}.

A file named *.test.jh is a test file. A test replaces the agent's reply with fixed text, so the test gives the same result on every run.

The first test below fails on purpose, so that you can see what a failed test prints. Its expected text leaves out the trailing :(. The second test passes.

#!/usr/bin/env jaiph

import "say_hello.jh" as hello

# We expect this test to fail due to mismatch in error message
# between the actual failure and the expected string in the test file:
# the expected string drops the trailing ":(". We use it to verify the
# test works and the error message output is correct.
test "without name, main fails with validation message" {
  # When
  const response = hello.main() allow_failure

  # Then
  expect_equal response "You provided an invalid name"
}

test "with name, returns greeting and logs response" {
  # Given
  const expected_response = "Hello Alice! Fun fact: Alice in Wonderland was written by Lewis Carroll."
  mock prompt expected_response

  # When
  const response = hello.main("Alice")

  # Then
  expect_equal response expected_response
}

#!/usr/bin/env jaiph

# a script body goes in '…' or '''…''' quotes
# it is bash by default; for another language, put the
# interpreter before the quotes: node'''…''', python3'''…'''
script check_report_exists = '''
  test -f report.txt
'''

export def main() {
  # when check_report_exists() fails, the recover body runs,
  # and then check_report_exists() runs again (up to 10 times)
  check_report_exists() recover (failure) {
    logerr "Failed to check report.txt"
    prompt "report.txt is missing. Create it with a short dummy summary."
  }

  # a script can also be written inline
  return 'cat report.txt'()
}

When a step fails, its recover body runs and then the step runs again, up to 10 times by default.

#!/usr/bin/env jaiph

channel findings -> analyst
channel report -> reviewer

def scanner() {
  log "Scanning for issues..."
  send "Found 3 issues in auth module" -> findings
}

def analyst(msg) {
  send "Summary: ${msg}" -> report
}

def reviewer(msg) {
  logerr "Critical issue: ${msg}"
}

export def main() {
  scanner()
}

A channel passes messages between defs. channel findings -> analyst calls analyst once for every message sent to findings.

#!/usr/bin/env jaiph

const prompt_text = "Say: Greetings! I am [model name]."

def cursor_say_hello(name) {
  config {
    agent.backend = "cursor"
  }
  const response = prompt "${prompt_text}"
  log response
}

def claude_say_hello(name) {
  config {
    agent.backend = "claude"
  }
  const response = prompt "${prompt_text}"
  log response
}

# main waits until both async calls finish
export def main(name) {
  async cursor_say_hello(name)
  async claude_say_hello(name)
}

async starts a call without waiting for it. Here Cursor and Claude get the same prompt at the same time, and main waits for both.

#!/usr/bin/env jaiph

# stdin connects scripts with ->, and the data streams
# from one script to the next without being held in memory
script gen = bash'''
  printf 'alpha\nbeta\ngamma\n'
'''

script upper = bash'''
  tr 'a-z' 'A-Z'
'''

script count = bash'''
  wc -l | tr -d ' '
'''

export def main() {
  # make three lines -> uppercase them -> count them
  const n = stdin gen() -> upper() -> count()
  return n
}

stdin connects scripts with ->. The first call produces the data, and each script after it reads stdin and writes stdout. The data streams from one script to the next, so a large output is never held in memory.
